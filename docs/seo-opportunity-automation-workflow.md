# SEO Opportunity Automation Workflow

## Purpose

This workflow gives every generated client website a repeatable, low-token process for finding
and building the pillar pages it is missing. It turns a Google Keyword Planner export plus the
site's own route tree into a ranked list of page opportunities, then drives each opportunity
through brief, build, supporting content, and QA. The mechanical steps run as deterministic Node
scripts so Claude Code spends tokens on judgment and content, not on parsing.

## Core Principle

Scripts parse, Claude decides. Anything that is deterministic (scanning routes, reading a CSV,
clustering keywords, scoring overlap) runs once in Node and is written to small compressed JSON
files. Claude online and Claude Code then read those summaries instead of re-crawling the repo or
re-reading thousands of CSV rows. No search volume, CPC, competition, or difficulty value is ever
invented. Keyword metrics come only from a user-supplied Keyword Planner export.

## Where This Fits in Site OS

This workflow is an ongoing-growth complement to the page-build system, not a replacement for it.
It feeds the existing prompts rather than competing with them:

- It produces opportunities that become inputs to the standard keyword, brief, and build prompts.
- It respects `docs/keyword-research-and-aeo-depth-standard.md` for any high-value page it spawns.
- It respects `docs/no-fake-data-policy.md` in full.
- It respects the Required Website Design Skill Pass for any page it builds.
- It uses the same `docs/site-os/` and Git discipline already defined for client repos.

The canonical scripts live in Site OS Master at `seo-automation/`. Generated client repos receive
scaffold copies. Site OS Master remains the single source of truth.

## Claude Online vs Claude Code Responsibility Split

Claude online (strategy):

- Generate seed topics and seed keywords for Keyword Planner.
- Review `opportunities.json` and recommend which pages to build.
- Write the SEO page brief.
- Plan supporting blog posts and internal links.

Claude Code (implementation in the client repo):

- Run the four scripts.
- Build the pillar page from the brief (metadata, schema, FAQs, internal links, CTAs).
- Wire internal links and supporting content.
- Run SEO QA.

The human operator runs the manual Keyword Planner export and drops the CSV into the repo.

## Generated Client Repo /docs/seo/ Folder Structure

The client repo carries a `docs/seo/` folder that holds both context and generated data:

```
docs/seo/
  business-context.md          context: who the business is and what it really offers
  seed-topics.md               context: the topic areas to seed Keyword Planner with
  service-map.md               context: real services and real service areas
  keyword-exports/             input: raw Keyword Planner CSV files (operator supplied)
  route-manifest.json          generated by scan-routes.mjs
  normalized-keywords.json     generated by parse-keyword-csv.mjs
  keyword-clusters.json        generated by cluster-keywords.mjs
  opportunities.json           generated by score-opportunities.mjs
```

The context markdown files are filled from the real client brief. They never describe services or
locations the business does not actually provide.

## Generated Client Repo seo-automation/ Folder Structure

The client repo also carries a scaffold copy of the script module:

```
seo-automation/
  README.md
  scripts/
    scan-routes.mjs
    parse-keyword-csv.mjs
    cluster-keywords.mjs
    score-opportunities.mjs
  templates/
    json-shapes.md
```

The scripts are zero-dependency Node modules. They are run from the client repo root.

## Keyword Planner Workflow

1. Claude online reads the `docs/seo/` context files and produces seed topics and seed keywords.
2. The operator opens Google Keyword Planner and uses those seeds to discover keywords.
3. The operator exports the results as a CSV.
4. The operator saves the CSV into `docs/seo/keyword-exports/`.

Site OS never fabricates this export. If no CSV is present, the parsing step exits cleanly and
nothing downstream runs.

## CSV Parsing Workflow

Run `parse-keyword-csv.mjs`. It reads the newest CSV in `docs/seo/keyword-exports/`, detects the
encoding (Keyword Planner often exports UTF-16 LE with a BOM), detects the delimiter (tab or
comma), finds the header row past any preamble lines, normalizes the standard columns,
deduplicates keywords case-insensitively, and writes `normalized-keywords.json`. Ranges such as
`1K - 10K` are preserved in a raw field and left out of the numeric field so no value is invented.

## Clustering Workflow

Run `cluster-keywords.mjs`. It reads `normalized-keywords.json` and groups keywords into topic
clusters by shared base tokens, then tags each cluster with detected modifiers and intent hints
across seven pattern families: service, location, audience, problem, comparison, cost, and
emergency. Each cluster records a metrics summary that aggregates only the volumes actually
supplied. Clustering is a deterministic token heuristic, not a semantic embedding model.

## Opportunity Scoring Workflow

Run `score-opportunities.mjs`. It reads `keyword-clusters.json` and `route-manifest.json`,
measures how strongly each cluster overlaps an existing route, and writes a ranked
`opportunities.json`. The score is a bounded build-priority heuristic with a transparent
breakdown (service fit, buyer intent, local intent, cluster depth, modifier strength, existing
overlap penalty, data completeness). The score is not keyword difficulty, ranking probability, or
a traffic estimate, and must never be presented as one. Clusters that already overlap an existing
route strongly are flagged for expansion instead of a duplicate new page.

## Pillar Page Selection Workflow

Claude online reads `opportunities.json` and recommends which opportunities to build, considering
real business priorities, conversion value, and existing coverage. The operator approves one
opportunity, which is recorded as `selected-opportunity.json` with a clear `build-new` or
`expand-existing` decision. This keeps the build auditable and prevents accidental duplicate pages.

## SEO Page Brief Workflow

For the selected opportunity, Claude online writes a structured `page-brief.json` containing the
meta title, meta description, H1, heading outline with keyword targets, direct-answer blocks,
FAQs, schema plan, internal links, primary CTA, and an explicit list of unsupported claims to
avoid. The brief must satisfy `docs/keyword-research-and-aeo-depth-standard.md` for high-value
pages. Headings, FAQs, and schema must align with each other and with content that will actually
appear on the page.

## Pillar Page Build Workflow

Claude Code builds the page in the client repo from `page-brief.json`. The build runs the Required
Website Design Skill Pass and produces:

- Unique meta title and meta description.
- One clear H1 and a logical H2 and H3 structure.
- Direct-answer blocks for AEO and voice search.
- A FAQ section that matches the FAQ schema exactly.
- Schema that matches visible content (WebPage, Service, FAQPage, BreadcrumbList, and others as
  applicable).
- Natural internal links to and from related routes.
- A clear primary CTA and a conversion path.

Build discipline follows the standard Gate 1, Gate 2, Gate 3 sequence and explicit per-file
staging. No invented reviews, ratings, prices, hours, or credentials.

## Supporting Blog and Internal Link Workflow

Claude online plans supporting content with `internal-link-plan.json`: a small set of supporting
blog posts that each target a related long-tail or question cluster and link up to the new pillar,
plus inbound links from existing pages and outbound links the pillar should provide. Anchors are
natural and varied, never exact-match stuffed. Links point only to routes that exist in
`route-manifest.json` or are planned in this same workflow.

## SEO QA Workflow

Claude Code runs SEO QA and writes `seo-qa-report.json`. QA verifies the meta title and
description are present and unique, there is exactly one H1, the heading hierarchy is valid, the
FAQs match the FAQ schema, internal links resolve to real routes, and no fake data is present. A
page cannot reach `pass` until `noFakeDataConfirmed` is true. A conditional pass carries forward
open items and is not a full pass.

## Token-Saving Rules

- Run the scripts once and reuse their JSON output. Do not ask Claude Code to re-scan routes or
  re-parse CSV rows a script already handled.
- Read the compressed JSON summaries, not the raw route tree or the full CSV.
- Use Claude online for strategy (seeds, selection, brief, link plan) and Claude Code only for
  implementation and QA.
- Do not regenerate a brief, cluster set, or opportunity list unless an input actually changed.
- Build one approved opportunity at a time. Do not bulk-generate pages that were not selected.
- Keep outputs compact. The scripts already strip the data down to what the next step needs.

## No-Fake-Data Rules

- Keyword metrics come only from the user-supplied Keyword Planner CSV.
- Scripts never invent search volume, CPC, competition, or keyword difficulty. Missing values are
  null.
- The opportunity `score` and its breakdown are internal priorities, not SEO metrics.
- Seeds, briefs, and pages describe only real services and real service areas.
- Schema is planned only for content that will actually appear on the page.
- No invented reviews, ratings, prices, hours, awards, or credentials anywhere in the pipeline.
- This workflow inherits `docs/no-fake-data-policy.md` in full.

## Final SOP

1. Fill the `docs/seo/` context files from the real client brief.
2. Claude online generates seed topics and seed keywords.
3. The operator exports a Keyword Planner CSV into `docs/seo/keyword-exports/`.
4. Run `scan-routes.mjs`.
5. Run `parse-keyword-csv.mjs`.
6. Run `cluster-keywords.mjs`.
7. Run `score-opportunities.mjs`.
8. Claude online reviews `opportunities.json` and recommends pages; the operator approves one.
9. Claude online writes the SEO page brief.
10. Claude Code builds the pillar page with metadata, schema, FAQs, internal links, and CTAs.
11. Claude online plans supporting blog posts and internal links; Claude Code wires them.
12. Claude Code runs SEO QA and records the result.

Repeat steps 8 through 12 for each approved opportunity. Re-run steps 3 through 7 only when there
is a new keyword export or the route tree changes.
